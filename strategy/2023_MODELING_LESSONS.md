# 2023 优秀论文代表性阅读：建模与写作方法总结

> 证据口径：2023 年 A—F 每题精读 1 篇代表论文，共 6/58 篇；同题其余 52 篇只做摘要、目录与建模路线概览。本文总结的是可迁移的解题框架，不是 2023 全体论文的方法频率统计，也不表示复现了作者代码或数值。

## 一、六类题共同展示出的建模思想

### 1. 先找“对象、关系、状态、接口”，再选算法

六题表面差异很大，但都能先画出结构：

- WLAN：节点、感知关系、干扰关系、退避状态和时隙事件；
- DFT 分解：目标矩阵、因子结构、稀疏/量化约束和误差接口；
- 竞赛评审：作品、专家、分配关系、评分尺度和复议流程；
- 双碳：核算量、驱动量、预测量、情景参数和决策变量；
- 脑卒中：患者、检查、临床时间、事件标签、轨迹和结局；
- 临近预报：多源观测、时空场、降水量和业务阈值。

可迁移原则是：先把名词变成对象，把文字关系变成图或约束，把各问的输入输出接起来。算法是处理某个接口的工具，不是论文主线。

### 2. 一个可复用内核，按问题逐层增加条件

高质量解法通常不为每小问另起炉灶，而是保留不变量：

- WLAN 保留退避状态机，只修改感知、干扰、丢包和握手机制；
- DFT 保留蝶形/分块结构，只增加稀疏、量化、Kronecker 和精度约束；
- 评审保留专家—作品二分图，再加入尺度校准、异常识别和多阶段流程；
- 双碳保留核算恒等式，再叠加基准预测和政策情景；
- 医疗保留患者时间轴，再分别派生风险、轨迹与预后任务；
- 气象保留同一数据立方体，再派生未来雷达场、QPE 和资料贡献。

写作时要显式指出“上一问输出如何进入下一问”，这样论文不是六个算法报告的拼接。

### 3. 复杂模型应由可观察缺陷触发

先做 baseline，再看缺陷：

| 观察到的缺陷 | 可考虑的升级 |
|---|---|
| 对称闭式模型无法覆盖非对称拓扑 | 节点级方程、图模型、离散事件仿真 |
| 精确矩阵分解被量化/稀疏约束破坏 | 近端交替、投影、整数或局部搜索 |
| 简单分配可行但不够均衡 | 最小费用流、MILP、Pareto/NSGA-II |
| 趋势模型回测残差仍有结构 | 带外生变量模型、状态空间、残差学习 |
| 总体轨迹残差揭示患者异质性 | 混合效应、轨迹聚类、DTW/函数型方法 |
| 雷达预报出现位移、强回波低估或多解 | 运动约束、加权/分位数损失、概率生成 |

“用了更复杂模型”不是创新；“指出简单模型具体失败在哪里，并用受控实验证明修正有效”才是完整论证。

### 4. 验证必须匹配结论层级

| 想支持的结论 | 至少需要的证据 |
|---|---|
| 程序实现一致 | 手算小例子、守恒/约束回代、另一实现对照 |
| 预测有效 | 独立单位切分、样本外测试、合理 baseline、置信区间 |
| 模型更稳健 | 参数扰动、不同随机种子、不同场景/事件/群体 |
| 方法可部署 | 真实时间可得特征、计算资源、失败模式、外部环境验证 |
| 变量具有贡献 | 去变量/替换消融，在同一训练协议下比较 |
| 政策/治疗有因果作用 | 识别假设、混杂控制、准实验或因果设计；普通相关不够 |

解析与仿真吻合、训练拟合度高、SHAP 权重大、图像更清晰，都只能支持有限结论。论文应主动写出证据边界，这不会削弱作品，反而让结论更可信。

## 二、看到什么问题，优先用什么工具

| 问题结构 | 首先问自己 | baseline | 常用升级 | 推荐工具 |
|---|---|---|---|---|
| 随机接入/排队/协议 | 状态、事件和时钟是什么 | Markov/更新过程 | 节点级非对称方程、离散事件 | SciPy、SimPy、NetworkX、ns-3 |
| 结构化矩阵/信号 | 是否存在递归、蝶形、低秩或积结构 | 精确小规模分解 | PALM/ADMM、投影、整数搜索 | NumPy、SciPy、CVXPY、Pyomo |
| 分配与制度设计 | 哪些是硬约束，公平指什么 | 随机/轮转可行解 | 匹配、流、MILP、Pareto | OR-Tools、Pyomo、Gurobi、NetworkX |
| 长期预测与政策 | 核算恒等式和情景参数是什么 | 朴素趋势/回归 | 状态空间、系统动力学、鲁棒规划 | statsmodels、LEAP、Vensim、Pyomo |
| 医疗表格与纵向数据 | 独立单位和预测时点是什么 | 逻辑/有序回归、简单曲线 | 混合效应、生存、轨迹聚类、集成 | sklearn、statsmodels、lifelines、tslearn |
| 时空场预测 | 持续性和运动外推有多强 | persistence/光流 | ConvLSTM/U-Net/Transformer/概率生成 | xarray、PyTorch、pySTEPS、MetPy |

比赛时间有限时，先用成熟库建立可复现 baseline；自写代码主要用于题目特有机制、约束或仿真。不要为显示工作量重写成熟统计检验、优化器和基础神经层。

## 三、四天比赛的论文结构建议

### 摘要

建议控制为一个总句加逐问句：

1. 一句说明对象、核心困难和总路线；
2. 每问一句包含“任务—关键抽象—方法—主要结果/验证”；
3. 结尾一句给适用范围、稳健性或业务价值；
4. 关键词 4—6 个，优先写问题结构和核心方法，不把所有算法都塞入。

数字必须带比较对象、单位和验证集。例如“相对持续性基线，60 min CSI 提高……”比“模型精度高”有效；不能独立验证的作者结果要标明口径。

### 第一章：问题重述与分析

- 用自己的语言重述任务，不大段复制赛题；
- 列每问输入、输出、难点和与上一问的接口；
- 给一张“对象—关系—数据流—决策”总图；
- 解释为什么先做 baseline、什么现象会触发升级模型。

### 数据、假设与符号

- 数据表按来源、时间范围、粒度、单位、缺失率、使用任务列出；
- 假设只写影响模型成立的假设，并说明若不成立会怎样；
- 符号按集合、参数、变量、指标分组，单位和索引范围写清；
- 在数据切分前明确独立样本单位和预测时点，避免泄漏。

### 各问建模章节

每章保持统一顺序：

```text
任务与难点
→ baseline 与不足
→ 模型抽象/假设
→ 目标、约束或状态转移
→ 求解流程与实现细节
→ 结果、对照与误差
→ 小结：本问输出如何进入下一问
```

公式后立刻解释变量、物理/业务含义和单位。算法原理只写与本题选择有关的部分，教材式推导和长代码放附录。

### 验证、评价与建议

- 把“模型内自洽、样本外预测、外部效度”分开写；
- 优点必须对应已展示证据，缺点必须具体到数据、假设或部署；
- 建议要绑定模型变量和触发条件，不能从相关性直接跳到政策/治疗结论；
- 最后一页优先放约束检查、敏感性和失败案例，而不是再增加一个新模型。

## 四、图表与机制图的可复用规范

### 一图一任务

- 场景图：定义对象和关系；
- 流程图：说明输入、处理、判断和输出；
- 机制图：解释状态、因果假设或模块接口；
- 结果图：支持一个明确结论；
- 诊断图：暴露残差、失效范围和不确定性。

同一张图不要同时承担模型总览、数据流程、算法细节和结果展示。

### 布局与字体

- 阅读方向固定为左到右或上到下，主路径用同一方向；
- 模块名采用“动词 + 对象”，如“构造事件标签”“求解分配方案”；
- 正文字体与论文一致，图内中文通常不小于正文的 70%—80%；
- 连接线尽量正交，避免交叉；回环放在外侧；对不同线型给图例；
- 只对关键节点加颜色，背景留白，边框统一粗细。

### 配色

推荐使用低饱和、色盲友好的 3—5 色系统：

- 数据/输入：蓝色系；
- 机理/计算：青绿系；
- 优化/决策：橙色系；
- 输出/验证：紫色或深绿；
- 风险/失败：红色只作强调，不大面积填充。

同一概念跨图保持同色。连续量用感知均匀色图；分类色与连续色不要混用；黑白打印时仍应靠线型、点型和标签区分。

### 结果图的比较纪律

- 同组面板必须共享坐标范围、色标、裁剪区域和单位；
- 理论—仿真用“线 + 点/置信带”，不要仅画两条难以区分的曲线；
- 多情景用同一历史段和目标线；
- 医疗/政策关联优先用森林图；组成随时间变化用堆积面积而非多张饼图；
- 图题写出比较对象和结论线索，图注说明样本量、误差条和统计口径。

## 五、比赛现场的最低质量门槛

1. 每个任务都有一个可解释 baseline。
2. 数据切分单位与部署对象一致。
3. 所有约束、单位、边界和类别编码都能回代检查。
4. 复杂模型至少有一次消融或与 baseline 的同口径比较。
5. 结论中的每个数字都能追到表、图、代码或计算记录。
6. 图表颜色、字体、坐标、有效位和名词全篇统一。
7. 摘要、正文、结论中的指标和模型名称一致。
8. 主动写明未完成外部验证、因果识别或工程实测的边界。

## 六、2023 六题带来的核心认识

2023 代表论文覆盖了随机机制、结构化数学构造、制度优化、长期情景、医疗纵向数据和时空深度学习。它们共同提示：建模的主线不是“掌握更多算法”，而是把现实问题转换为合适的对象、关系、状态、约束和证据。真正可迁移的能力是：知道什么时候应保留解析结构，什么时候需要仿真；什么时候该做预测，什么时候只能做条件情景；什么时候模型重要性只是关联，什么时候需要消融或因果设计；以及怎样让每一张图、每一个公式和每一段结论都服务于同一条证据链。
