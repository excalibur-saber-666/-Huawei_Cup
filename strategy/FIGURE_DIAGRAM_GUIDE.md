# 数模论文图表、机制图与结构图指南

> **适用范围**：用于四天数模比赛中的技术路线图、机制图、模型结构图、算法流程图、数据图和空间图。本文结合 2025 A—F 各 1 篇代表论文的图形表达进行归纳，并吸收通用科学制图规范；它是可迁移工作法，不是对全部 145 篇论文的风格统计。

## 先记住一句话

一张好图不是“把做过的步骤都放进去”，而是让读者在 5—10 秒内看懂：**输入是什么，核心机制是什么，输出是什么，这张图支持什么结论。**

画图前先写一句带动词的核心结论，例如：

> 多源观测经过时空对齐和可靠性加权后，形成统一风险场，并驱动避险路径优化。

如果一个框、箭头或子图不能帮助说明这句话，就删除、合并或移入正文/附录。

## 一页式速查

### 比赛制图默认样式卡

以后没有特殊要求时，机制图、原理图和结构图默认从这套样式开始，而不是临时挑颜色。

| 项目 | 默认规范 |
|---|---|
| 画布 | 按论文最终尺寸绘制；单栏约 7.5—8 cm，通栏约 15.5—16.5 cm |
| 背景 | 纯白；分组区用 4%—8% 浅色底，不用大面积高饱和色 |
| 中文字体 | 思源黑体 / Noto Sans CJK SC；不可用时选微软雅黑 |
| 英文与数字 | Arial / Source Sans 3；全图只用一个英文字体族 |
| 数学公式 | Cambria Math 或论文公式字体，公式不要截图 |
| 字号 | 组标题 11—12 pt；模块 9—10 pt；注释/坐标 8—9 pt；最终不低于约 8 pt |
| 字重 | 标题 SemiBold，模块 Regular/Medium；不用大段粗体 |
| 边框 | 深灰或主色，0.75—1.0 pt；不要纯黑粗边框包围所有对象 |
| 主箭头 | 1.5—2.0 pt，主色；次级关系 0.75—1.0 pt 或虚线 |
| 圆角 | 同类框统一圆角，避免矩形、胶囊、云朵等随意混用 |
| 框内边距 | 上下左右约 0.15—0.25 cm，文字不要贴边 |
| 模块间距 | 同组约 0.3—0.5 cm；组间约 0.6—1.0 cm |
| 颜色数量 | 1 个主色族 + 1 个辅助色族 + 1 个强调色 + 中性色 |
| 阴影/渐变 | 默认不用；只有表达层级悬浮时才用极弱阴影 |
| 导出 | 优先 SVG/PDF；必须位图时按最终尺寸导出 300 dpi 以上 PNG |

字体选型服从“清楚、统一、可嵌入”。若比赛模板对字体有明确要求，以模板为准；交稿前必须在导出的 PDF 中检查是否发生字体替换。

### 四套可直接用的配色

配色先分配语义，再分配颜色。一个颜色在全文只能承担一种稳定含义。

| 方案 | 主色 | 辅助色 | 强调色 | 浅底色 | 适用场景 |
|---|---|---|---|---|---|
| 科技蓝青 | `#2563EB` | `#0F766E` | `#EA580C` | `#EFF6FF` / `#F0FDFA` | 模型结构、数据融合、工程系统 |
| 稳重蓝橙 | `#0072B2` | `#56B4E9` | `#E69F00` | `#EEF6FA` / `#FFF7E6` | 对照、优化、算法流程 |
| 自然青绿 | `#168AAD` | `#52B788` | `#F4A261` | `#EDF8F7` / `#F2FAF5` | 生态、环境、空间与园林 |
| 克制紫青 | `#6D5BD0` | `#2A9D8F` | `#E76F51` | `#F3F0FF` / `#ECFAF8` | 抽象机制、评价与多模态 |

共同中性色：正文 `#1F2937`，次级文字 `#4B5563`，辅助线 `#CBD5E1`，极浅分隔 `#E5E7EB`。

- 连续数值优先使用 Viridis/Cividis 一类感知均匀色图。
- 正负偏差使用蓝—白—红发散色图，并让 0 对应中性色。
- 类别超过 6 个时，不再仅靠颜色区分，应增加分面、符号或直接标注。
- 红色只用于风险、错误或关键警示；不要把普通步骤画成大红块。

### 内容密度预算

一张通栏机制图通常控制在：

- 3—5 个一级分组；
- 5—9 个主节点；
- 1 条主路径，最多 2 条次级支路；
- 1 个框不超过 2 行，核心标签约 4—10 个汉字；
- 图例不超过 5 项；
- 内部文字层级不超过 3 级。

超出预算时，优先拆成“总览图 + 局部结构图”，而不是缩小字体。

### 从空白页到成图的六步

1. **写结论句**：先写这张图要让读者复述的唯一一句话。
2. **列对象**：只列输入、核心机制、中间状态、输出和验证，不列所有操作细节。
3. **灰度排版**：全部使用灰框，先确定阅读方向、分组、留白和主次。
4. **压缩文字**：把句子改成“动作 + 对象”，删除重复、空话和可移入图注的解释。
5. **赋予语义色**：主流程一种颜色，另一类对象一种颜色，关键结论一个强调色。
6. **缩放检查**：按论文最终尺寸查看；做 10 秒复述、黑白打印和 PDF 导出检查。

顺序不能反过来。先上色再组织内容，通常会得到“漂亮但读不懂”的图。

### 通用五层图法

```text
任务/结论
  ↓
输入对象
  ↓
核心变换或机制
  ↓
中间状态/关键变量
  ↓
输出 + 验证
```

复杂问题也不要突破这五层；应在某一层内部做分组，而不是不断增加平行框。

### 图型选择

| 你要回答的问题 | 首选图型 | 主视觉对象 |
|---|---|---|
| 全文或各问如何衔接 | 总体技术路线图 | 问题模块、接口、最终交付 |
| 数据怎样变成结论 | 数据处理流水线 | 数据源、处理、特征、模型、结果 |
| 为什么会产生某种现象 | 机理/因果机制图 | 实体、状态、作用方向、反馈 |
| 模型内部如何计算 | 系统/模型结构图 | 层、模块、张量/变量、融合点 |
| 算法怎样迭代 | 算法流程图 | 初始化、循环体、判断、终止 |
| 位置、路径、风险怎样分布 | 地图/GIS/路径图 | 底图、空间场、起终点、路径 |
| 一个结论有哪些证据 | 多面板证据图 | 主证据 + 对比 + 诊断/稳健性 |
| 模型是否可靠 | 对比/消融/敏感性图 | baseline、误差、不确定性、扰动 |
| 对象如何从二维恢复到三维 | 重构/对象层级图 | 坐标变换、局部对象、整体网络 |

### 最低合格线

- 一图一主旨；标题能说出图回答的问题。
- 阅读方向唯一：默认左→右或上→下，不让主箭头来回折返。
- 颜色有语义：同一对象全文同色，强调色只给关键结果或异常。
- 正文缩放到最终版面后，最小文字仍能看清。
- 箭头表示真实的信息、因果、控制或迭代关系，而非装饰。
- 图注脱离正文仍可读懂颜色、形状、缩写和数据范围。
- 结果图有轴名、单位、样本范围、图例；比较图说明误差或区间。

## 图型选择决策树

```text
这张图主要解释“过程”吗？
├─ 是
│  ├─ 有判断/循环？                    → 算法流程图
│  ├─ 强调模块间输入输出？              → 系统/模型结构图
│  ├─ 强调原因、作用和反馈？            → 机理图
│  └─ 强调全文/多问关系？               → 总体技术路线图
└─ 否
   ├─ 主要展示空间位置、路径或场？        → GIS/路径/热力图
   ├─ 主要展示数值比较、趋势或不确定性？  → 统计图/多面板证据图
   ├─ 主要展示图像识别或重构效果？        → 原图—处理—输出 + 定量面板
   └─ 主要展示对象分类和层级？            → 层级图/对象关系图
```

不要用一张“万能流程图”同时承担原理、算法、结果和验证。若一张图需要读一分钟才能找到入口，应拆成“概览图 + 局部图/证据图”。

## 机制图：画关系，不堆算法名

### 思考顺序

1. **确定观察对象**：系统中真正存在的实体是什么，如传感器、故障源、道路、园林单元、信号域。
2. **确定状态变量**：什么随时间、空间或工况变化，如温度、风险、特征分布、连通概率。
3. **确定作用关系**：谁影响谁，方向是什么，是促进、抑制、传递、观测还是约束。
4. **确定模型对应**：数学模型分别描述哪一实体、状态或关系。
5. **确定可验证输出**：哪张结果图或哪个指标能验证这个机制链。

### 推荐骨架

```text
[现实驱动/输入] ──作用──> [中间状态] ──触发/调节──> [目标现象]
       │                         │                         │
     观测量                    模型变量                    可验证指标
       └──────────── 数据/反馈 ──┴───────────────> [校准或决策]
```

图中应优先写现实含义，算法名放在第二层或小字说明。例如主框写“域差异消除”，副标签再写“DANN + MMD”，比只放“DANN、MMD、ResNet”更易懂。

### 线条语法

| 视觉元素 | 固定语义 |
|---|---|
| 实线单箭头 | 主信息流、计算流或因果方向 |
| 双向箭头 | 确有双向交互或耦合，避免滥用 |
| 虚线箭头 | 监督、参考、约束或可选支路 |
| 回环箭头 | 迭代、反馈或再训练 |
| 无箭头连线 | 归属、对应或结构关系 |
| 外层浅色容器 | 同一阶段、子系统或作用域 |

必须在图内或图注明确特殊线型含义。不要让线穿过文字和关键框；交叉无法避免时使用跳线、汇流点或拆图。

## 结构图：先边界，再模块，再接口

系统/模型结构图按以下顺序画：

1. 系统边界或阶段容器；
2. 输入与输出；
3. 3—7 个一级模块；
4. 一级模块之间的接口；
5. 只有对理解关键机制必要时，才展开二级模块。

推荐形式：

```text
输入层             核心模型层                    输出与验证层
[数据 A] ─┐       ┌─[模块 1]─┐
[数据 B] ─┼─> [对齐/融合] ─> [核心状态] ─> [预测/决策] ─> [验证]
[先验 C] ─┘       └─[模块 2]─┘                         └─> [解释]
```

- 相同层级的框同尺寸；核心模块可以更大，但不能只是颜色更艳。
- 输入、处理、输出使用不同的浅色族；算法名称不应各用一种颜色。
- 卷积层、网络层很多时，只画功能段和维度变化，完整参数表放正文或附录。
- 融合点必须说明是拼接、加权、平均、注意力还是后验组合。

## 总体技术路线图：同时说明“各问”和“接口”

优秀总图通常包含两种关系：

1. **每一问内部**：输入 → 建模 → 求解 → 结果 → 验证；
2. **问题之间**：上一问的哪个输出，成为下一问的哪个输入。

推荐用三列或四列并行，每列代表一问；在列间用一条清楚的接口箭头连接。不要把所有公式、结果截图和小图塞进总图。总图只保留：

- 数据/先验；
- 核心任务；
- 方法功能；
- 关键中间量；
- 本问输出；
- 输往下一问的接口。

总图中的框文字尽量采用“动词 + 对象”，如“对齐多源时间戳”“构建风险场”“优化受约束路径”，少用“问题一处理”“模型建立”等空标签。

## 算法流程图：图形必须有语法

| 形状 | 用法 |
|---|---|
| 圆角矩形 | 开始、结束 |
| 矩形 | 处理、计算、更新 |
| 菱形 | 能回答“是/否”的判断 |
| 平行四边形 | 输入、输出 |
| 虚线容器 | 循环体、并行体、可选模块 |

规则：

- 判断框写问题，如“达到终止条件？”，两条边直接标“是/否”。
- 回边沿图外缘返回，不穿过循环体内部。
- 同一循环只保留一个入口；多个终止条件可合并后在正文定义。
- 流程图表达控制逻辑，公式留在正文；框内只写关键操作。
- 初始化、约束修复、评价、更新和终止是优化算法最容易漏掉的五个环节。

## 数据流水线：防止泄漏也靠图说明

数据类题建议画成：

```text
原始数据
  ↓ 数据字典/质量检查
分组划分 ───────────────────────────────┐
  ↓                                    │
训练侧拟合预处理 → 特征/模型训练 → 验证  │
  ↓                                    │
冻结变换与模型 ←─────────────────────────┘
  ↓
测试/目标域推理 → 指标、误差和解释
```

应在图中明确：划分发生在何时，标准化/特征选择在哪一侧拟合，训练和推理有哪些共享模块，哪些标签在目标域不可见。这样结构图本身就能帮助发现数据泄漏。

## 结果图和多面板证据图

### 一张图的证据层级

```text
主证据（最大、最清楚）
├─ 对照或 baseline
├─ 误差/残差/不确定性
└─ 稳健性、敏感性或消融
```

不要默认把所有面板做成一样大。决定结论的主图应占 35%—60% 面积，其余证据围绕它服务。

### 常见任务的首选结果图

| 任务 | 推荐 | 少用/不用 |
|---|---|---|
| 时间趋势 | 折线 + 区间带 | 3D 折线、平滑到掩盖原始波动 |
| 类别比较 | 点图/箱线/小提琴/有基线的条形图 | 仅用饼图、截断纵轴制造差异 |
| 预测效果 | 真值—预测、残差、校准、误差分布 | 只报一个平均指标 |
| 分类诊断 | 混淆矩阵、ROC/PR、类别指标 | 只给准确率 |
| 空间场 | 等值线/热力图 + 统一色标 | 彩虹色图、每幅图不同范围 |
| 路径优化 | 底图 + 候选/最优路径 + 风险/约束 | 只有路径线，没有起终点和比例尺 |
| 聚类/降维 | 散点 + 直接标注 + 聚类质量 | 把二维分离写成高维已证明分离 |
| 敏感性 | 参数—指标曲线/热图 | 只选一个参数点声称鲁棒 |
| 消融 | 统一基线的点图/条形图 | 不同数据划分下直接比较 |

### 多面板统一

- 同一变量跨面板用同色、同符号、同名称。
- 可比较的轴统一范围；若不能统一，必须显式说明。
- 共享一个图例，或直接在线尾/对象旁标注。
- 面板编号 a、b、c 放在固定左上角，大小一致。
- 主图在左上或顶部；阅读顺序与正文引用顺序一致。
- 每个面板只回答一个问题，遮住某面板不影响论证时应删掉。

## 空间图、路径图与三维图

### 空间图必须有

- 坐标系/投影或经纬度；
- 比例尺、方向或足以定位的坐标刻度；
- 数据范围与时间范围；
- 色标名称和单位；
- 缺失区、不可行区、边界和约束区的区分；
- 起点、终点、观测点与候选路径的明确符号。

连续量使用感知均匀的连续色图；正负偏差用以 0 为中心的发散色图；类别使用离散色板。不同时间或不同方法比较时，必须锁定同一色标范围。

### 三维图的使用条件

只有当第三维是真实空间维或对结论不可替代时使用三维图。若主要任务是比较数值，二维投影、切片、等值线或小多图往往更准确。三维图应同时给：

- 视角和轴单位；
- 颜色代表的变量；
- 至少一个二维投影/切片；
- 避免遮挡的透明度或稀疏显示策略。

## 美观不是“颜色多”：视觉规范

### 配色

一张图通常只需要：

- 中性色：文字、边框、辅助线；
- 主色族：主流程或主要方法；
- 强调色：关键输出、异常或决策点。

可直接使用的稳妥组合：

| 用途 | 色值 |
|---|---|
| 文字/深边框 | `#1F2937` |
| 辅助灰 | `#9CA3AF` |
| 主蓝 | `#2563EB` |
| 辅助青 | `#0F766E` |
| 强调橙 | `#EA580C` |
| 风险红（少量） | `#DC2626` |
| 浅蓝背景 | `#EFF6FF` |
| 浅青背景 | `#F0FDFA` |
| 浅橙背景 | `#FFF7ED` |

不要同时使用大红、大绿、亮黄、亮蓝作大面积底色。红绿色同时编码时必须再加形状、线型或文字，照顾色觉差异与黑白打印。

### 字体与字号

- 中文统一用一种无衬线字体，英文/数字可用 Arial、Calibri 或同类字体。
- 最终插入论文后，图内正文建议不小于 8 pt，核心标签 9—11 pt，图中小标题 11—13 pt。
- 同一级别字号一致；不要靠缩小字号解决内容过多。
- 框内尽量不超过两行，每行 6—12 个汉字；长说明移到图注。

### 线、框、圆角和阴影

- 普通边框约 0.75—1.25 pt，主流程箭头约 1.25—2 pt。
- 同级框保持同圆角、同边距、同线宽。
- 辅助网格线浅于数据线；背景容器只用极浅填充。
- 少用渐变、立体边框、强阴影和发光；它们不表达数据语义。
- 箭头头部大小一致；同一语义不要混用五种箭头样式。

### 对齐与留白

- 用网格对齐，框间距保持一致；模块内边距不少于文字高度的约 0.5 倍。
- 先留白再加装饰。空白能建立分组，避免用更多边框分组。
- 图的外边距、分栏间距和面板间距应形成稳定节奏。
- 主路径周围保留更大留白，让读者自然先看到它。

## 图中文字怎么写

框内文字按以下优先级：

1. 功能或动作：`计算连通概率`；
2. 对象：`裂隙实例`；
3. 必要时加方法：`DBSCAN 初聚类`；
4. 参数、公式和解释放正文或图注。

避免：

- `进行数据处理`、`建立模型`、`得到结果`等空话；
- 一框塞入完整句子；
- 缩写未解释；
- 方法名代替现实功能；
- 同义词来回变化，如“目标域/测试域/新域”混用。

## 图题、图注与正文配合

### 图题模板

- 技术路线：`图 N  多源数据对齐、融合与风险决策的总体技术路线`
- 机制图：`图 N  工况变化经特征漂移影响故障判别的作用机制`
- 结构图：`图 N  物理约束与数据驱动融合模型的结构`
- 算法图：`图 N  带约束修复的遗传算法求解流程`
- 结果图：`图 N  不同模型在独立测试集上的误差与校准表现`

不要只写“模型图”“结果图”“流程图”。图题应说明对象和目的，但不在标题里塞结论数字。

### 自足图注模板

```text
图 N | [名词短语总题]。
a，[面板展示什么、颜色/形状分别表示什么]；
b，[比较对象、坐标和单位]；
c，[验证/稳健性内容]。
误差线为[标准差/标准误/置信区间]，n=[样本量]；检验为[方法]。
```

图注至少交代颜色/形状映射、缩写、样本范围、单位、误差类型和必要统计信息。正文则回答：**图中最重要的变化是什么，它支持哪条结论，适用边界是什么。** 不要只写“结果如图所示”。

### 正文三句式

1. `图 N 展示了……`：说明图回答什么问题；
2. `与……相比，……在……范围内……`：指出可核验差异；
3. `这支持……，但该结论限于……`：给出含义和边界。

实践建议：先用纸笔或 PowerPoint 灰框搭结构，确认主路径后再上色；统计图从代码直接导出，避免截图；流程图和机制图优先保存可编辑源文件及矢量版本。

### PowerPoint / diagrams.net 实际画法

1. 把页面尺寸设为图的最终宽度，如通栏图设约 `16 cm × 9—11 cm`，不要先画超大图再无限缩小。
2. 打开网格、参考线和吸附；先放 3—5 个透明分组容器，再放主节点。
3. 使用“对齐”和“横向/纵向分布”，不要靠肉眼逐个拖位置。
4. 只使用连接符，不用普通直线冒充箭头；这样移动框时线仍保持连接。
5. 先完成一组“标准框 + 标准箭头 + 标准标题”，复制它们生成全图，避免样式漂移。
6. 用选择窗格给对象命名并分组；背景容器锁定在底层，主路径保持在最上层。
7. 全选后检查字体、字号、边框、箭头和颜色是否只有约定的几种。
8. 保存可编辑源文件；优先导出 SVG/PDF，再插入论文。若 Word 对 SVG 支持不稳定，另存 300—600 dpi PNG 备用。

不要用截图粘贴公式和统计图。公式在 Word/PowerPoint 中重新输入，统计图由代码导出，再在矢量编辑器中做最少量的字体和对齐修整。

### Python 统计图的默认外观

- 先确定最终物理尺寸，再设置 `figsize` 和导出 dpi。
- 去掉上、右边框；网格只保留浅灰主网格。
- 线宽、点大小、误差线帽宽在全文统一。
- 标题尽量放在图题/图注中，图内保留必要的小标题。
- 图例优先放空白区；固定类别可在线尾直接标注。
- 保存源数据、绘图脚本和输出图，禁止在 Word 中手工改数据位置。
- 比较图使用同一数据划分、同一轴范围和同一指标定义。

推荐统一主题逻辑：白底、深灰文字、主蓝数据线、橙色强调、浅灰网格；空间连续场改用 Viridis/Cividis，相关矩阵或正负误差改用以 0 为中心的发散色图。

### 最终修图只做三件事

1. 对齐：边缘、中心、间距、面板编号和图例。
2. 统一：字体、字号、颜色、线宽、箭头、符号和命名。
3. 删减：重复标题、无意义边框、装饰图标、过长说明和不支撑结论的面板。

不要在最终修图阶段改变数据、坐标轴范围或统计结果；这些修改必须回到绘图代码和原始数据。

## 四天比赛的制图流程

### 第一天：建立视觉语言

- 确定全文字体、主色、强调色、线宽和图例规则。
- 画一张粗略总路线图，检查各问输入输出和接口。
- 建立图表清单：图号、结论、数据源、负责人、状态。
- 先画数据概览和关键难点图，帮助团队统一理解。

### 第二天：模型图和第一版结果

- 为每个核心模型画结构/机制草图。
- 代码端统一绘图主题、尺寸、色板和导出函数。
- 主结果同时保留误差、残差或不确定性证据。
- 写图题和一句核心结论，防止后期图文脱节。

### 第三天：形成证据链

- 补齐 baseline、消融、敏感性、稳健性和异常案例。
- 合并多面板，统一轴范围、图例、面板顺序和颜色。
- 对空间图锁定色标，对比较图锁定数据划分和指标口径。
- 让一名未参与画图的队员做“10 秒复述测试”。

### 第四天：排版与复核

- 所有图插入最终版面后按实际尺寸检查字号。
- 对照代码核对数值、单位、图例、样本量和版本。
- 检查正文首次引用顺序、图题、图注、交叉引用和分页。
- 导出 PDF 后再次检查字体替换、线条缺失、图片模糊和色差。

## 10 秒复述测试

把图给未参与该部分建模的队友，只允许看 10 秒，然后问：

1. 这张图的入口和出口是什么？
2. 哪一条是主路径？
3. 最关键的中间量是什么？
4. 颜色和箭头分别表示什么？
5. 这张图想支持什么结论？

答不出时优先删减、重排和直接标注，不要继续加装饰。

## 最后原则

图的高级感主要来自**删减、对齐、层级和一致性**，不是渐变、阴影和更多颜色。比赛时间有限时，宁可做一张能独立讲清模型逻辑的图，也不要做三张信息重复、无法复核的装饰图。
