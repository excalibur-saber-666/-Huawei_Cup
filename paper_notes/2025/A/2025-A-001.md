## 基本信息与主线

- 题目：通用神经网络处理器下的核内调度问题

- 题型：DAG 拓扑调度、缓存峰值最小化、地址分配与换入换出、多资源流水线仿真、约束多目标优化。
- 全文最值得学习的是“逐问递进而不是逐问换模型”：问题一优化调度顺序，问题二在该顺序上增加真实缓存约束，问题三再把执行时间纳入。上一问既提供下一问的初始解，也提供对照基线。

## 建模过程：这篇论文是怎样一步步做的

### 第一步：把工程描述抽象成计算图和缓冲区生命周期

作者先把 NPU 运算表示成有向无环图：节点是 ALLOC、FREE、COPY、计算等操作，边表示依赖。一个调度序列必须满足拓扑关系；ALLOC 到 FREE 之间是 buffer 的驻留区间，所有同时存活的 buffer 大小之和形成缓存占用曲线。

这个抽象很关键：它把硬件术语转化为三类熟悉的数学对象——DAG 排序、区间资源占用、有限容量分配。遇到复杂工程题时，可以先问：对象是什么、关系是什么、状态怎样随时间变化、资源约束作用在哪一层。

### 第二步：问题一只解决“顺序怎样减少峰值”

作者没有一开始就联合处理全部约束，而是先忽略地址与容量，只改变满足拓扑序的节点顺序。先用贪心、深度优先、关键路径三种策略生成不同风格的初始解，再用模拟退火做节点重插入，优化最大驻留量。

这里可迁移的思想是“多起点 + 局部改进”：

- 贪心适合快速得到可行解；
- 关键路径适合重视长依赖链；
- 深度优先倾向尽快走完一条分支、释放相关数据；
- 模拟退火适合可行解容易构造、精确搜索太大、且存在自然邻域操作的排列优化。

作者报告六个实例的峰值为 7660、14040、4500、7588、9216、34816 字节。比赛中更重要的不是记住这些数，而是学会画“缓存驻留量—调度步骤”曲线，用它解释某种排序为什么能提前释放内存。

### 第三步：问题二把顺序、地址与 SPILL 分层处理

有了调度序列后，作者继续决定 buffer 放在哪级缓存、地址如何分配、容量不足时哪些数据换出/换入。论文采用“调度序列优化—缓存分配—SPILL”分层框架：小规模用 ILP 表达精确约束，大规模用 rounding、彩色边图和启发式策略控制求解时间。

这是四天比赛里很实用的处理方式：强耦合问题可以先按因果顺序拆开，每一层先给出可行方案，再做少量回溯，而不必一开始建立难以求解的巨型联合模型。作者报告六例额外搬运量为 23752、35344、17148、45820、12288、60416。

模型选择可按规模分流：

- 实例小、约束可线性化：ILP/CP-SAT，用于获得精确基准；
- buffer 生命周期近似区间：interval graph、linear scan、best-fit；
- 图规模大且需要快速可行解：rounding、贪心、局部搜索；
- 只有容量确实不足时才引入 SPILL，避免把额外搬运当作默认动作。

### 第四步：问题三从单目标走向约束多目标

前两问主要关注内存，第三问加入总执行时间。作者用负载感知优先级促进不同硬件单元并行，用时序敏感的缓存分配降低等待，再联合考虑执行时间与搬运量。

这里最重要的思路是先分清“目标”和“不能突破的约束”。如果题目说搬运量最多增加 5%，可采用 ε-constraint：把 `搬运量 ≤ 1.05×基线` 固定为硬约束，在可行域内最小化执行时间；如果题目允许方案选择，再画 Pareto 前沿。论文第三问也诚实展示了部分案例改善、部分案例退化，提示我们不同计算图可能需要不同权重和不同邻域，不能指望一个固定策略包打天下。

## 什么情况下用什么模型

| 观察到的问题结构 | 优先模型/工具 | 使用条件与理由 |
|---|---|---|
| 有向依赖、只能从就绪任务中选下一个 | 拓扑排序、list scheduling、关键路径 | 先确保可行，再设计优先级；适合问题一的 baseline |
| 决策是一个巨大排列，目标可快速计算 | 模拟退火、禁忌搜索、大邻域搜索 | 能构造保持拓扑可行的邻域；需多初始解和重复运行 |
| 小规模离散决策、约束明确 | MILP、CP-SAT | 可提供精确最优或 gap，适合给启发式算法当标尺 |
| buffer 有开始/结束时刻且争用地址 | 区间图、linear scan、best-fit | 生命周期可近似为区间；实现简单、解释清楚 |
| 容量不足、需要换入换出 | 动态 SPILL、分层贪心、局部搜索 | 先保证地址合法，再优化搬运次数或字节量 |
| 两个目标冲突且一个有明确容忍上界 | ε-constraint、分层优化 | 先满足硬上界，再优化主目标，比赛中最稳妥 |
| 需要展示多种可选折中 | NSGA-II 等 Pareto 搜索 | 有足够时间、多次运行预算和清晰选点规则时再用 |
| 执行时间来自多硬件单元并行 | 事件驱动仿真、甘特图、关键路径 | 静态求和不够；需模拟资源占用、等待和流水线 |

建议工具：NetworkX 处理 DAG；OR-Tools CP-SAT 或 Pyomo + Gurobi/SCIP 做小规模精确基准；NumPy/pandas 做数据审计；SimPy 或自写事件队列做流水线；Matplotlib 绘制驻留曲线、甘特图和 Pareto 前沿。

## 四天比赛中可复用的推进方式

1. 第一天：读题并画对象—关系—资源图；写可行性检查器；完成最简单拓扑排序和指标计算。
2. 第二天：完成问题一 baseline 与一类局部改进；一边出结果一边写定义、假设、目标和算法伪代码。
3. 第三天：加入容量、地址和 SPILL；小实例做精确基准，大实例做启发式；开始统一结果表和图。
4. 第四天前半：加入执行时间和多目标策略，只做能稳定解释的升级；完成敏感性、对照和失败案例分析。
5. 第四天后半：摘要从结果表提取，检查单位、符号、编号、图题和前后数据；删除不能支持结论的夸张措辞。

## 写作手法与篇幅组织

- 摘要采用“三问三段”：每段写任务本质、核心方法和一组代表结果，适合递进题。最前面用一两句交代统一框架，最后一句说明应用意义。
- 正文约 42 页，问题一约占 13 页、问题二约 14 页、问题三约 8 页，最后 2 页做模型评价与总结。篇幅与建模工作量基本匹配：基础定义和前两问写得更充分，第三问复用前文符号和模型。
- 每一问都按“问题分析 → 数学模型 → 算法 → 伪代码 → 结果表 → 分案例解释”展开，读者容易追踪。
- 图表分工较清楚：驻留曲线解释生命周期，缓存柱图/饼图解释资源构成，表格集中比较六个实例。图后立即写结论，不让图表孤立。
- 论文用“多策略初始解”“分层求解”“按算子类型分析”串起全文，体现了统一框架下的适配，而不是简单堆砌算法名。
- 模型评价按三个问题分别写“优点—局限—改进”，适合作为比赛论文结尾模板；其中失败案例也可转化成下一步改进方向。

## 我会怎样改造成更稳的比赛模板

1. 先给一张全题关系图：调度序列决定生命周期，生命周期影响地址与 SPILL，三者共同影响执行时间。
2. 每问开头用一个小表列出决策变量、目标、硬约束、输入与输出。
3. 每次升级都回答“baseline 出现了什么缺陷，所以引入什么模型”，避免算法堆砌。
4. 结果表同时放 baseline、改进值、改善率、运行时间和是否可行；随机算法补充多次运行分布。
5. 小规模精确解与大规模启发式并列：前者证明质量，后者证明可扩展性。
6. 摘要中的实例名和数值由最终结果表自动生成，减少赶稿时的复制错误。
