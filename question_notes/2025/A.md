# 2025 A 题：通用 NPU 核内调度与缓存优化

> 状态：`partial` 代表性阅读。已精读 1/4 篇（2025-A-001）并核对关键 PDF 页面；其余 3 篇只完成摘要、目录、模型路线和可迁移思路概览，仍为 `pending`。

## 赛题应该怎样思考

这道题表面是 NPU 工程问题，抽象后是递进式组合优化：

1. 在 DAG 拓扑约束下调整执行顺序，缩短 buffer 生命周期并降低驻留峰值；
2. 在有限多级缓存中分配地址，容量不足时决定 SPILL；
3. 联合考虑硬件单元并行、流水线时间和数据搬运，寻找受约束的多目标折中。

因此，合理的思考顺序不是先选“高级算法”，而是先把计算图、buffer 生命周期、地址空间、硬件资源和时间模型分层。上一问的最优/较优方案要保留为下一问的初始解和 baseline，三问才能形成一条完整证据链。

## 什么情况选什么模型

### 1. 先用拓扑排序和贪心建立 baseline

当任务有明确依赖、每一步只能从就绪集合选节点时，先用 Kahn 拓扑排序/list scheduling。优先级可围绕：尽早 FREE、缩短关键路径、结束大 buffer 生命周期、提高某硬件单元利用率。

贪心适合比赛第一版，因为它容易实现、一定能解释、能快速产生完整结果。后续算法都应与它同口径比较。

### 2. 排列空间太大但邻域自然时，用局部/元启发式

如果简单贪心的驻留峰值较高，并且可以定义“节点重插入、交换、局部重排”等保持拓扑可行的操作，可使用模拟退火、禁忌搜索或大邻域搜索：

- 模拟退火：希望偶尔接受较差解以跳出局部最优；实现最简洁；
- 禁忌搜索：重复回到旧解明显、需要短期记忆时；
- 遗传/粒子群：变量同时包含排序、离散缓存选择和 SPILL 决策，单一邻域难覆盖时。

四天比赛中，除非复杂算法带来稳定改善，否则保留简单方法往往更利于解释和写作。

### 3. 小规模用精确优化，大规模用启发式

约束能写成线性/逻辑形式，且实例不大时，用 MILP 或 CP-SAT 求精确解；它的主要价值是给出最优值或 gap，帮助判断启发式解到底好不好。大实例再使用 rounding、分层贪心或局部搜索，形成“精确性 + 可扩展性”组合。

### 4. 生命周期明确时，用区间分配思想

buffer 从 ALLOC 到 FREE 的存活时间近似一个区间。重叠区间不能占用同一地址，可使用区间图着色、linear scan、first-fit/best-fit。只有容量不够时才插入 SPILL，并把换入换出次数、搬运字节和碎片率分开报告。

### 5. 多目标先用 ε-constraint，再考虑 Pareto 算法

若题目明确“搬运量最多增加 5%”，最稳的方法是把它作为硬约束，再最小化执行时间。若需要给决策者多种方案，再使用 NSGA-II/MOPSO 等画 Pareto 前沿，并解释最终选点。不要先随意加权，否则权重容易掩盖题目真正的底线。

### 6. 有并行硬件资源时，用事件驱动仿真

总执行时间不是节点 cycles 的简单相加。Cube、Vector、MTE 等单元可能并行或等待，应维护事件队列、资源占用和依赖释放时刻，输出甘特图、关键路径和空闲原因。可使用 SimPy，也可自写优先队列模拟器。

## 一套可直接执行的建模流程

1. 画全题关系图，定义 DAG、节点类型、buffer、缓存层级和硬件单元。
2. 写统一的指标计算器和可行性检查器；所有算法共用，避免比较口径变化。
3. 完成确定性贪心 baseline，并输出六个实例的驻留曲线。
4. 小图用 OR-Tools CP-SAT / Pyomo + Gurobi/SCIP 求精确基准，大图用 SA/禁忌/大邻域搜索。
5. 从调度序列计算生命周期，做地址分配；容量不足再设计 SPILL。
6. 建事件驱动时间模型，先验证简单手算案例，再跑全部实例。
7. 用 ε-constraint 完成第三问；有余力再生成 Pareto 前沿。
8. 做多随机种子、参数敏感性和规模扩展；结果表同时报告质量、耗时和可行性。

## 写作模板

### 摘要

开头 2—3 句说明工程背景、核心矛盾和统一框架；随后每问一段，固定写：任务本质 → 模型/算法 → 代表结果 → 解释；结尾说明可迁移价值。摘要不要堆完整公式，也不要只罗列算法名。

### 正文

1. 问题重述：把工程语言转为决策变量、目标和约束。
2. 问题分析：画三问依赖图，说明为什么逐层求解。
3. 模型假设与符号：只保留后文真正使用的内容，符号带单位。
4. 每一问按“baseline → 发现不足 → 升级模型 → 算法 → 验证 → 小结”写。
5. 模型评价：按问题分别写优势、适用范围、计算成本和可改进点。
6. 总结：回到三问主线，不再引入正文没有证明的新结论。

### 图表

- 全题关系图：解释三问怎样递进；
- 缓存驻留阶梯图：解释峰值从哪里来；
- 地址—时间图：解释重叠和碎片；
- 甘特图：解释并行与等待；
- Pareto 前沿：解释时间—搬运折中；
- 总表：baseline、改进值、改善率、耗时、可行性一表汇总。

图后紧跟一句“这张图证明什么”，标题和图例使用统一术语与单位。

## 从本题提炼出的通用思维

1. 先拆结构，再选算法；模型名称不能代替问题抽象。
2. 先有简单可行解，再由其缺陷触发升级。
3. 强耦合问题优先分层，只有层间损失明显时再联合优化。
4. 精确模型负责标尺，启发式负责规模，仿真负责工程时间，多目标模型负责决策。
5. 上一问的结果要成为下一问的 baseline，保证论文是一条链而不是三篇小论文。
6. 写作与建模同步推进：每得到一个稳定结果，就完成对应公式、伪代码、图表和解释。
