## 这类题的本质

这是“带先后依赖的多资源流水线调度”。领域对象是 P4 基本块，但数学骨架是：

    控制流/变量读写 → 依赖 DAG → 关键路径与资源下界
    → ready set 优先级排布 → 逐级资源校验 → 瓶颈灵敏度

问题二的共享资源规则，本质上是修改资源冲突图/占用算子，而不是重新选择一个无关模型。

## 通用解题框架

1. 重建 CFG，核对节点数、边数、入口、出口和是否为 DAG。
2. 从读写集合构造数据依赖，明确 RAW/WAR/WAW 是否要求严格跨级；从支配/后支配或题目定义构造控制依赖。
3. 合并为先后约束 DAG，计算拓扑序、关键路径和每个节点的最早级/最晚级。
4. 计算两个下界：关键路径长度，以及各类总资源量/每级容量的资源下界。
5. 选择求解器：小规模 MILP/CP-SAT；大规模 list scheduling，以关键剩余路径、资源稀缺度和后继数排序。
6. 问题二把“是否同一执行流程”预计算为冲突/兼容关系，封装 HASH、ALU 占用函数。
7. 对结果逐边、逐级回代，并用资源上限扫描定位瓶颈。

## 模型和工具选择

| 条件 | 推荐方法 | 工具与验证 |
|---|---|---|
| 图规模中小、需最优证明 | MILP、CP-SAT、branch-and-cut | Gurobi/SCIP/OR-Tools；gap、上下界 |
| 约束量巨大 | 分解、cut generation、column/constraint generation | 每轮违规约束数、收敛界限 |
| 图大、实时/快速方案 | 关键路径 list scheduling、beam search | 与下界/小规模精确解比较 |
| 资源共享依赖路径互斥 | 冲突图、最大同时占用、路径集合/分离算法 | 共享核算逐路径验证 |
| 需要寻找瓶颈 | 利用率 + 资源上限灵敏度 | 总级数—容量阶梯曲线、边际收益 |
| 改善启发式 | 局部搜索、SA、GA、PSO | 多种子分布、可行率、耗时 |

## 写作和图表模板

- 摘要：节点/依赖/资源抽象 → 算法 → 两问级数 → 可行性与瓶颈。
- 正文：数据预处理 → 依赖定义 → 图模型 → 下界 → 排布算法 → 校验与复杂度。
- 总体图：两问采用同一布局，用高亮标出问题二修改的共享资源计算。
- DAG 图：只画关键子图或分层统计，全量 607 节点应提供交互/附件而非塞入正文。
- 资源图：同一颜色固定一种资源；利用率和容量灵敏度分图，不用双轴混淆。
- 结果表：总级数、下界、gap、运行时间、每级资源峰值/均值、违规数必须同时出现。
